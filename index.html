Accuracy, precision, recall and F1

1The confusion matrix

Precision, recall and the F1 score are all built from four counts in a classic machine-learning tool called the confusion matrix. Take a model designed to detect spam emails. Every email it sees lands in exactly one of four cells.

Predicted spam
Predicted not spam
Actually spam
True positive (TP)Says spam, and it is spam. Correct.
False negative (FN)Says not spam, but it is spam. Wrong (Type II error).
Actually clean
False positive (FP)Says spam, but it is clean. Wrong (Type I error).
True negative (TN)Says not spam, and it is clean. Correct.

The four metrics below look at the same model from different angles.

2Accuracy: overall correctness

Accuracy is the simplest metric: the share of all predictions, spam or not, that the model got right.

Out of every email the model looked at, how many did it classify correctly?

Accuracy =TP + TNTP + FP + FN + TN

When it matters most: when the classes are roughly balanced and every kind of mistake costs about the same. It is the easiest number to explain, but it can be dangerously misleading when one class is rare.

Worked example. A disease test screens 1,000 patients, only 20 of whom are actually sick. A lazy model that predicts “healthy” for everyone gets 980 right and 20 wrong.

Accuracy = 980 / 1,000 = 0.98 — yet it catches zero sick patients. Recall is 0, so the headline number hides a useless model.

3Precision: quality of positive predictions

Precision measures how reliable the model is when it predicts the positive class.

When the model predicts an email is spam, how often is it actually right?

Precision =TPTP + FP

When it matters most: when the cost of a false positive is high. A spam filter needs high precision, because sending an important work email (a false positive) to the spam folder is a major problem.

4Recall (sensitivity): how many positives are found

Recall measures the model’s ability to find all the positive cases in the dataset.

Out of all the actual spam emails in the inbox, how many did the model manage to catch?

Recall =TPTP + FN

When it matters most: when the cost of a false negative is high. In cancer screening or fraud detection, letting a sick patient or a thief slip by undetected (a false negative) is dangerous. You want high recall, even if it means raising a few false alarms.

5F1 score: the balance

Most problems face a precision–recall trade-off. Tune a model to catch absolutely everything (high recall) and it will make more mistakes (low precision). Make it so strict that it only predicts positive when it is certain (high precision) and it will miss many cases (low recall).

The F1 score balances the two. It is the harmonic mean of precision and recall rather than the ordinary average, so if either one is very low the F1 score collapses with it.

F1 = 2 ×Precision × RecallPrecision + Recall

Substituting the two formulas above gives a version that works straight from the counts, which is handy for numericals:

F1 =2·TP2·TP + FP + FN

Worked example. Out of 200 emails, the model has TP = 45, FP = 5, FN = 15 and TN = 135.

Precision = 45 / 50 = 0.90. Recall = 45 / 60 = 0.75.

F1 = 2 × 0.90 × 0.75 / (0.90 + 0.75) = 1.35 / 1.65 ≈ 0.818. With the shortcut: 90 / (90 + 5 + 15) = 90 / 110 ≈ 0.818.

The plain average would have been 0.825. The harmonic mean sits a little lower, pulled toward the weaker of the two.

True negatives appear in none of these formulas. Precision, recall and F1 only look at how the model handles the positive class, which is why they are preferred over plain accuracy when positives are rare.
